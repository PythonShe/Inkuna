# Inkuna Core v1.0 — Library, Import, Progress, Sessions, Settings

## Problem & context

Both native shells are complete UI prototypes running on hardcoded
`PlaceholderLibrary` fixtures; 34 `TODO(core)` markers point at the Rust core
for real data. The core today (`core/` workspace, ~770 lines) has a single
`publications` table (schema `user_version = 1`, already shipped — iOS opens
the DB), a metadata-only EPUB parser (no spine, TOC, or cover), and a minimal
async FFI surface (`Bookshelf`: `import` / `list` / `set_progression` /
`remove`). Import neither copies files nor dedupes; covers, chapters,
bookmarks, reading sessions, stats, and settings do not exist in the core at
all. No import UI has ever shipped, so real-world v1 databases contain no
publications — only dev installs do.

Core v1.0 is the surface that lets both shells delete their placeholders and
run on real data. Per project principle, this is **not an MVP**: the
architecture (storage ownership, concurrency model, schema) is designed as the
long-term base; only genuinely independent features (search engine, format
normalization, sync) are staged into later specs.

A load-bearing fact from the shell audit: **every page number in the UI is
fictional** (`currentPage`, `pageCount`, chapter pages, "p. 564 of 1418").
Neither the core nor Readium has absolute pages. The substitute is Readium's
**synthetic positions** (~1024-character units), which make "page" counts and
"pages read" stats honest and computable.

### Terminology (used throughout)

- **`progression`** — Readium's **`totalProgression`**: book-wide, `0.0..=1.0`.
  Never the per-resource `locations.progression`. All auto-finish and stats
  logic reads this book-wide value.
- **`position`** — Readium's book-wide synthetic position, 1-based
  (`locations.position` with `positionCount` as denominator).
- **Locator** — the Readium locator JSON blob. Opaque to the core: stored and
  returned, never parsed. (Locators carry `href`, `title`, and `text`
  before/highlight/after context — shells render bookmark rows and jump
  targets from the blob itself.)
- **Resource** — one spine item (reading-order document) of an EPUB.
- **Chapter** — one entry of the flattened TOC (nav doc / NCX). Chapters and
  resources are *different sets*: a chapter points into a resource via
  `href` (possibly with a fragment); a resource may hold several chapters or
  none.

## Goals / non-goals

**Goals**

- Both shells can delete `PlaceholderLibrary.swift` / `.kt` and every
  `TODO(core)` in library, detail, reader-contents, tonight, stats, and
  settings code paths — **except** the Wishlist segment, which stays a
  visible-but-empty (or shell-hidden) segment until its own spec.
- Core owns book storage: import copies the file, extracts metadata, cover,
  TOC, and per-resource plain text (the future search corpus) in one pass.
- Import is idempotent (content-hash dedupe) and crash-safe (a DB row always
  points at an existing file; no half-imported state survives).
- Reading progress is a Readium locator plus normalized
  progression/position; one FFI call per page turn.
- Reading sessions power every number on the Stats screen; the core returns
  numbers only, shells format and localize.
- Reads never block behind writes: WAL with a single-writer / reader-pool
  split from day one.
- Settings live in the core with core-owned defaults.
- Every subsystem tested with CJK fixtures.

**Non-goals**

- No full-text in-book search engine (tantivy + jieba) — separate spec; this
  spec only produces its raw-text corpus (`resource_text`). Segmentation,
  indexing, and highlight-back anchoring are that spec's decisions; raw
  per-resource text is a stable input to any of them.
- No format normalization: non-EPUB files are detected and rejected with the
  format named. MOBI/AZW3/TXT/CBZ/CBR pipelines are later specs on the same
  import surface.
- No Wishlist shelf, no file-less publications, no collections — deferred.
- No sync, no annotations/highlights, no rendering or pagination in the core.
- No bookmark notes/labels (no UI for them yet; the locator blob already
  carries what a list row needs).

## Approach

**Single `Bookshelf` facade + core-owned storage.** One UniFFI object, one
SQLite DB, and the core owns a data directory handed to `open()`. Rejected:
shell-owned files (file logic duplicated ×2 platforms and drifts; cover/text
extraction would re-open files the core doesn't own) and multiple FFI objects
(no performance difference — every UniFFI call costs the same and all objects
would share the same DB; namespacing isn't worth the plumbing, and methods
are grouped so a later split is mechanical).

`inkuna-core` stays sync pure Rust; `inkuna-ffi` keeps the
`spawn_blocking`-based async wrapper. New capability lands in `inkuna-core`
with tests first, then a minimal FFI mirror (repo layering rule).

### Storage layout

```
<data_dir>/
  inkuna.db          # single SQLite DB, WAL, user_version migrations
  books/<id>.epub    # imported files, copied in by the core, named by publication id
  covers/<id>.<ext>  # extracted cover art; absent → shells use their seeded generated cover
  index/             # reserved for the search spec; not created in v1.0
```

**Path rule:** the DB stores every file path **relative to `data_dir`**
(`books/<id>.epub`); the FFI layer absolutizes on read. iOS container paths
change across installs/updates, so absolute paths must never be persisted.
The core never deletes a file outside `data_dir`.

Shells pass Application Support / `filesDir` once at startup and stop
managing book files. Breaking constructor change (`open(db_path)` →
`open(data_dir)`) is acceptable: the only current consumer is iOS
`LibraryStore`, which opens and does nothing else.

### Concurrency model

- **One writer connection** behind a `Mutex`, mutations only, each in a
  transaction. File I/O and parsing always happen outside the lock.
- **Fixed reader pool** for all queries, so list/stats/TOC reads never queue
  behind an import. **Decision: a minimal hand-rolled checkout pool** —
  `Mutex<Vec<Connection>>` + `Condvar`, 4 connections, blocking checkout
  (callers already run on `spawn_blocking` threads, which bounds waiters).
  `r2d2-sqlite` is rejected now rather than left as a build-time branch: it
  historically lags rusqlite releases, and the repo's stack policy
  disqualifies any crate that pins rusqlite below latest. `deadpool-sqlite`
  remains the designated upgrade if the core ever goes async-native.
- Every connection: `journal_mode=WAL`, `synchronous=NORMAL`,
  `busy_timeout`, `foreign_keys=ON`; rusqlite cached prepared statements.

## Components & interfaces

### Data model (migration v2, additive on shipped v1)

`publications` gains:

| column | type | meaning |
|---|---|---|
| `content_hash` | TEXT + unique index | BLAKE3 hex of the file; dedupe key |
| `cover_path` | TEXT NULL | relative path under `covers/`; NULL = no art |
| `finished_at` | INTEGER NULL | non-NULL = Finished shelf; powers "books this year" |
| `last_opened_at` | INTEGER NULL | Tonight hero + recently-opened ordering |
| `locator` | TEXT NULL | current position: opaque Readium locator JSON |
| `position_count` | INTEGER NULL | Readium synthetic position count, reported by shell |

**Legacy-row adoption (part of migration v2):** v1 rows hold external
absolute paths to files the core never copied (dev installs only — import UI
never shipped). Migration adopts each row: copy the file into `books/<id>.epub`,
compute `content_hash`, rewrite `file_path` relative; if the source file is
missing or unreadable, **drop the row**. After migration, every surviving row
is core-owned — `remove()` is always safe and dedupe always has a hash. The
migration test covers both the adopt and drop paths.

New tables (all FKs `ON DELETE CASCADE` so `remove()` cascades):

- `resources(id, publication_id, spine_idx, href)` — the spine, in reading
  order.
- `resource_text(resource_id, body TEXT)` — plain text extracted at import,
  one row per resource. Unread in v1.0; it is the search spec's raw corpus,
  complete even for books with no TOC.
- `chapters(id, publication_id, idx, title, href, depth)` — flattened TOC
  (EPUB 3 nav doc, NCX fallback). `href` (which may carry a fragment) is the
  Readium jump target; mapping a chapter to its resource is
  `href`-minus-fragment matched against `resources.href`, done at query time
  when needed — never stored, since it's derivable.
- `bookmarks(id, publication_id, locator TEXT, progression REAL, created_at)`.
- `sessions(id, publication_id, started_at, ended_at NULL, updated_at,
  start_progression, end_progression, start_position NULL, end_position NULL)`.
  **Invariant: at most one open session (`ended_at IS NULL`) per
  publication** — enforced by `session_start` (below).
- `settings(id INTEGER PK CHECK(id=1), onboarded, reading_theme,
  text_size_step, brightness)` — single row, defaults owned by the core.

Existing conventions unchanged: UUIDv4 string ids, unix-seconds `i64`
timestamps, authors stored `\u{1F}`-joined but exposed as `Vec<String>`
(shells join for display).

### Import pipeline

`import(path)`; `import_batch(paths)` parallelizes the parse stage with
`rayon` (designated crate; batch exists because both platforms' document
pickers multi-select and import UI is the roadmap's next step — the batch
layer reuses the single-import pipeline verbatim):

1. **Single streaming pass** — read the source once, computing BLAKE3
   (`blake3` crate: mainstream, SIMD-parallel, several× faster than SHA-256
   on large files) while copying to `books/<uuid>.epub.tmp`.
2. **Dedupe** — hash already present → delete tmp, return
   `ImportOutcome::Duplicate` with the existing publication. Import is
   idempotent; restores re-import cleanly.
3. **Parse the copy** — full OPF metadata (title, creators, language,
   extending the current parser); TOC (nav doc → NCX fallback); cover
   (EPUB 3 `cover-image` property → EPUB 2 `<meta name="cover">` fallback),
   stored as-is under `covers/` (shells handle display sizing); plain-text
   extraction of every spine item into `resource_text`, rayon across
   resources.
4. **Atomic commit** — rename tmp to `books/<id>.epub` **first**, then
   insert all rows in one transaction. A crash between rename and commit
   leaves an unreferenced file, never a fileless row; `open()` sweeps
   `books/` and `covers/` files unreferenced by any row, plus stray `.tmp`
   files. Any parse failure deletes the tmp/renamed file before returning.
   Invariant: **a committed row always points at an existing file.**
5. Non-EPUB → `UnsupportedFormat` with the detected format named, so shells
   can say "MOBI support is coming", not "error".

### Progress & positions

- `update_progress(id, locator_json, progression, position)` — one call per
  page turn (`position` optional until the shell knows it); a single writer
  transaction that updates the publication row (locator, progression,
  `last_opened_at`) and — if that publication has an open session — the
  session's end-state (`end_progression`, `end_position`) and `updated_at`
  heartbeat. With no open session it updates the publication only; never an
  error.
- `report_position_count(id, count)` — once per book after the shell's
  navigator computes synthetic positions; from then on "page N of M" is real.
- **Finishing.** Auto-finish is **transition-triggered**: `finished_at` is
  set only when an `update_progress` call crosses `progression >= 0.995`
  from below (Readium's end-of-book `totalProgression` is not guaranteed to
  land on exactly 1.0). `set_finished(id, true)` sets it explicitly;
  `set_finished(id, false)` clears it, and because the trigger requires an
  upward *crossing*, subsequent updates at-or-above the threshold do **not**
  re-finish — explicit unfinish sticks until the user leaves and re-reaches
  the end. `set_finished` stays in the surface because unfinishing is
  impossible without it once auto-finish exists.

### Sessions & stats

- `session_start(pub_id) -> session_id` at reader open: first retroactively
  closes any open session for this publication (`ended_at = updated_at` —
  the crash-recovery rule, applied lazily), then stamps `started_at`,
  snapshots current progression/position as start-state, sets
  `last_opened_at`. This enforces the one-open-session invariant.
- `session_end(session_id)` at reader close / app background.
- **Attribution rule (all stats buckets):** a session belongs wholly to the
  local calendar day/week/month/year of its `started_at` — calendar dots,
  weekly pages, and monthly minutes all use the same rule (a session is one
  sitting; splitting across midnight buys nothing).
- **Effective end** of a session = `ended_at`, or `updated_at` when NULL
  (in-flight session viewed mid-reading, or crashed session not yet swept).
- `stats_overview(tz_offset_minutes, week_starts_monday) -> StatsOverview`:
  - `pages_this_week` = Σ over this week's sessions of
    `max(0, end_position − start_position)`; sessions with NULL positions
    contribute 0 pages (but still count for time and dots).
  - `minutes_this_month` = Σ over this month's sessions of
    `(effective_end − started_at) / 60`.
  - `books_finished_this_year` = count of `finished_at` in the local year.
  - `read_days` = day-of-month numbers (current local month) having ≥1
    session.
  - **Numbers only, never formatted strings** — shells own formatting and
    l10n ("6½", localized month names). Local-time math via chrono
    `FixedOffset` from the passed offset.

### Library queries & metadata search

- `list(shelf, sort)` — server-side filtering: shelf `Reading` (opened,
  unfinished) / `Finished` / `All`; sort `RecentlyOpened` (Tonight hero =
  first row) / `RecentlyAdded`. (A `Title` sort is deliberately omitted — no
  shell affordance exists; UniFFI enum variants are additive later.)
- `publication(id)` for detail refresh.
- `search_library(query)` — case-folded, CJK-safe substring over
  title + authors, matched in Rust (proper Unicode casefolding, never SQL
  `LOWER`). Metadata search only; in-book full-text search is the search
  spec's engine over this spec's corpus.

### Settings

`settings() -> Settings` / `set_settings(Settings)` — whole-record
read/write, two FFI calls total. **Core-owned defaults:** `onboarded =
false`, `reading_theme = "paper"`, `text_size_step = 2`, `brightness =
0.78`. The core clamps on write (`text_size_step` 0..=4, `brightness`
0.0..=1.0); `reading_theme` is an opaque identifier string (shells own the
palettes; unknown ids are stored as-is so themes can ship shell-first).
**Takeover:** on first run against a core with default settings, each shell
seeds the core once from its legacy store (UserDefaults / DataStore) before
first read, then never touches the legacy store again — no user is silently
reset to un-onboarded. New fields arrive by migration.

### FFI surface (complete)

`Bookshelf` (UniFFI object, async via tokio, all methods
`Result<_, InkunaError>`; `Bookshelf` stays `Send + Sync` for Swift 6 strict
concurrency; naming honors the JNA collision rule — never `Library`):

```
open(data_dir: String)                                  — constructor
import(path: String) -> ImportOutcome                   — Imported | Duplicate
                                                          (hard I/O failures throw)
import_batch(paths: Vec<String>) -> Vec<ImportOutcome>  — per-item Failed instead
                                                          of throwing
list(shelf: Shelf, sort: Sort) -> Vec<Publication>
publication(id: String) -> Publication
remove(id: String)                                      — row (cascades) + book
                                                          file + cover
search_library(query: String) -> Vec<Publication>
update_progress(id: String, locator: String,
                progression: f64, position: Option<u32>)
report_position_count(id: String, count: u32)
set_finished(id: String, finished: bool)
chapters(id: String) -> Vec<Chapter>
add_bookmark(id: String, locator: String,
             progression: f64) -> Bookmark
bookmarks(id: String) -> Vec<Bookmark>                  — sorted by progression
remove_bookmark(bookmark_id: String)

session_end(session_id: String)
stats_overview(tz_offset_minutes: i32,
               week_starts_monday: bool) -> StatsOverview
settings() -> Settings
set_settings(settings: Settings)

```

Records (owned-value mirrors of core types with `From` conversions; paths
absolute in records, relative in the DB):

```

              language: Option<String>, format: Format, file_path: String,
              cover_path: Option<String>, added_at: i64, progression: f64,
              locator: Option<String>, position_count: Option<u32>,
              finished_at: Option<i64>, last_opened_at: Option<i64> }

              progression: f64, created_at: i64 }

                books_finished_this_year: u32, read_days: Vec<u8> }
Settings    { onboarded: bool, reading_theme: String, text_size_step: u8,
              brightness: f64 }
```

Enums: `Shelf { Reading, Finished, All }`; `Sort { RecentlyOpened,
RecentlyAdded }`; `ImportOutcome { Imported(Publication),
Duplicate(Publication), Failed { path: String, message: String } }`;
`Format` (existing). Errors: the existing `CoreError` → `InkunaError`
mirror — `Io`, `Database`, `Archive`, `UnsupportedFormat`,
`InvalidPublication`, `NotFound` — extended variant-for-variant if new
failure classes emerge, never stringly.

After any `inkuna-ffi` change both `scripts/build-core-*.sh` regenerate
bindings before shell work.

## Data flow

- **Import**: shell document picker → source URL → `import()` → core streams
  copy + hash → parse → rename → one transaction (publication + resources +
  resource_text + chapters) → `ImportOutcome` back to shell.
- **Reading**: shell opens book → `session_start` → Readium navigator emits
  locators on page turns → `update_progress` (one write: publication row +
  session heartbeat) → close → `session_end`.
- **Screens**: Library/Tonight/Search/Detail/Stats each make one coarse read
  call (`list` / `search_library` / `publication`+`chapters` /
  `stats_overview`) through the reader pool.

## Error handling & edge cases

- Existing `CoreError` → `InkunaError` mirroring continues; `.unwrap()` /
  `.expect()` forbidden outside tests.
- Non-EPUB import → `UnsupportedFormat` naming the detected format.
- EPUB with no TOC → empty `chapters`; the corpus (`resource_text`) is still
  complete because it keys off the spine. No cover → `cover_path` NULL.
  Malformed spine item → that resource's text row is skipped (logged),
  import still succeeds; metadata with no title falls back to file stem
  (current behavior).
- Duplicate import → `ImportOutcome::Duplicate`, never an error, on both the
  single and batch paths.
- Crash mid-import → unreferenced files and stray `.tmp`s swept at next
  `open()`; a committed row always points at an existing file.
- Crashed reading session → closed retroactively at `updated_at` by the next
  `session_start` for that publication; until then, stats read it via the
  effective-end rule.
- `update_progress` with no open session → publication-only update, no
  error.
- Unfinish-then-keep-reading → no re-finish (transition-triggered
  threshold, see Progress & positions).
- Negative reading delta (user pages backwards) → clamped to 0 in stats.
- `remove()` deletes row (cascades), book file, and cover — always inside
  `data_dir`; missing files are not an error (idempotent).
- Legacy v1 rows with missing source files are dropped at migration (see
  Data model).

## Testing strategy

Inline `#[cfg(test)]` beside code, `tempfile` fixtures, no binaries in git.
`write_epub` grows spine content, TOC, and cover so import tests exercise
the full pipeline. Required coverage:

- **CJK fixtures throughout** — metadata, TOC titles, resource text
  (`月光書房` / `紫式部` pattern), UTF-8-safe casefold in `search_library`.
- **Migration** — construct a v1 DB with rows whose files exist and rows
  whose files are missing; open; assert v2 schema, adopted rows (copied,
  hashed, relative paths), dropped rows.
- **Dedupe** — same file twice → `Duplicate`; byte-identical copy under
  another name → `Duplicate`.
- **Corpus completeness** — a no-TOC EPUB yields empty `chapters` but full
  `resource_text`; chapter→resource href mapping resolves fragments.
- **Crash recovery** — unreferenced book/cover files and `.tmp`s swept;
  open session closed retroactively by the next `session_start`.
- **Finish semantics** — auto-finish fires on upward crossing only;
  unfinish sticks at end-of-book; explicit finish/unfinish round-trips.
- **Concurrency** — reads succeed while a (slow, large-fixture) import runs:
  the reader pool actually delivers.
- **Stats** — session aggregation across a local-month boundary with a
  non-UTC offset (attribution by `started_at`); clamped negative deltas;
  NULL-position sessions count minutes/dots but 0 pages; in-flight session
  counted via effective end.
- **Settings** — clamping on write; defaults on fresh DB.
- Format detection, metadata parsing, DB roundtrips stay covered (existing
  rule).

## Open questions / assumptions

- **Idle time counts as reading time** within a session; shells are
  responsible for ending sessions on background/scene-inactive. No idle-gap
  clamping in v1.0.
- **Locators round-trip**: assumes both Readium toolkits emit and accept
  locator JSON faithfully, and that locator `title`/`text` fields are
  populated well enough for bookmark rows (if not, a bookmark list spec adds
  columns by migration).
- **Position counts arrive late**: until the shell reports
  `position_count`, position-based UI has no denominator and shells show
  progression-only; NULL-position sessions contribute time but not pages.
- **Cover bytes stored as-is** (no core-side resize/transcode); assumes
  shells can decode any image format an EPUB legally embeds.
- **Reader pool size 4** is a starting point, not measured; revisit with
  profiling.
- **`import_batch` write serialization**: parse is parallel, DB commits
  serialize per-item on the writer; assumed acceptable because parsing
  dominates — unmeasured, revisit if batch import feels slow.
- **Extraction cost is paid at import**: per-resource text roughly doubles a
  book's DB footprint and adds parse time; accepted deliberately (the
  alternative — a backfill re-parse when search lands — was rejected as a
  second cold pass over every book on a mobile device).

## Out of scope

- Full-text search engine (tantivy + jieba) — own spec; raw corpus ships
  here, segmentation/indexing decisions do not.
- MOBI/AZW3/TXT normalization, CBZ/CBR, PDF — later specs on this import
  surface.
- Wishlist / file-less publications / collections — deferred product
  decisions; the Wishlist segment stays empty (or hidden) in the shells.
- Bookmark list UI contract beyond the stored locator — a future spec may
  add columns by migration.
- Sync (WASM on Workers), annotations/highlights, bookmark notes — later.
- Watch-folder import (`notify`) — desktop-era feature.
